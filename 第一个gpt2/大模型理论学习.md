# 大模型理论学习

## 1 数值精度
### 1.1 导入
真实的大模型不是只算一次，而是：
- 有数十亿甚至数千亿个权重；
- 每个词都会转化成很多数字；
- 这些数字经过大量矩阵乘法；
- 最后得到下一个词的概率。
>所以，大模型里的“精度问题”，本质上是在问：这些数字，究竟要保存和计算得多精确？

比如数字 1.234567：
- 高精度可能保存成 1.234567
- 低精度可能只能保存成 1.23
- 更低精度可能只能保存成 1
后面的计算就会产生一些差异。

### 1.2 计算机常见精度
计算机通常用“科学计数法”的思路表示小数。
浮点数类似，只不过计算机使用的是二进制：
数字 = 符号 × 尾数 × 2^指数 

一个浮点数主要包含三部分：
符号位 sign
指数位 exponent
尾数位 mantissa

>所以，评价一个数字格式时，通常要看两个方面：
能表示多大的范围？
能表示多细的差别？

常见浮点格式的位分配如下：
格式	符号位	指数位	尾数位
FP32	1	8	23
FP16	1	5	10
BF16	1	8	7

比如说一个用FP16表示的二进制数： 0 10001 1010000000
- 符号位0表示正数 
- 指数使用偏置值 15：实际指数 = E - 15
- 尾数位 正规数默认有一个隐藏的 1：实际尾数 = 1.F
放到这个例子里面
- S=0
- E=10001₂=17，实际指数为 17-15=2
- 尾数是 1.101₂=1.625
- 所以：$1.625\times2^2=6.5$

FP32 的特点是：
- 指数位多，范围大；
- 尾数位多，精度高；
- 占用显存和带宽较多。

它常被作为“比较可靠的标准格式”。

FP16 比 FP32 少了一半位数：
- 显存占用约减半；
- 计算和传输通常更快；
- 但指数位只有 5 位，能表示的范围较小；
- 数值太大时更容易溢出。

FP16 的尾数比 BF16 多，所以在相近数值附近，FP16 通常表示得更细。

### 1.3 大模型到底用什么精度
1. 权重
权重是模型训练出来的参数，例如：
0.1357、-1.204、2.83
推理时它们会被反复使用。
2. 激活值
输入经过某一层计算后产生的中间结果，叫激活值。
输入 → 第1层 → 激活值 → 第2层 → 激活值 → ...
激活值会随着输入变化。
3. 梯度
训练时，模型需要根据误差调整权重，这些调整方向就是梯度。
推理阶段通常不需要梯度。
4. 累加结果
矩阵乘法中会把很多乘积加在一起：
a₁b₁ + a₂b₂ + a₃b₃ + ...
单个数字精度不够时，长时间累加可能放大误差，所以累加过程有时会使用更高精度。

因此，大模型不一定会“所有地方都用同一种精度”，而可能是：
权重：BF16
激活值：BF16
累加：FP32
梯度：FP32 或 BF16
>这就是混合精度的基础。核心思想是：不太敏感的计算使用低精度，容易积累误差的计算使用高精度。现在先进的大模型通常不是“整个模型统一使用某一种精度”，而是采用“混合精度 + 分块缩放 + 敏感部分保留高精度”。

### 1.4 具体而言

#### 1.4.1 训练时
训练最耗时的部分通常是矩阵乘法，所以先进方案会让矩阵乘法使用 FP8，甚至开始探索 FP4。
FP8 还会区分用途：
- 前向传播的权重、激活值：更注重精度，常用 E4M3；
- 反向传播的梯度：更注重数值范围，常用 E5M2。

公开的 DeepSeek-V3 技术报告也明确提到使用了 FP8 混合精度训练，并报告了稳定的训练过程。

#### 1.4.2 推理时
推理比训练简单一些，因为不需要计算梯度。常见做法是：
权重：INT4 / INT8 / FP8
激活值：FP16 / BF16 / FP8
敏感计算：保持更高精度

所以所谓“4-bit 模型”，通常不是每一个东西都用 4 bit，而可能只是：
大部分权重：INT4
部分层：INT8
激活值：FP16
Softmax、归一化：FP32 或 BF16
>最先进的核心不是单纯追求“位数越低越好”，而是判断：
哪些地方可以大胆降低精度，哪些地方必须保护精度。

### 1.5 什么叫量化
>量化，简单说，就是把原本可以取很多精细数值的高精度数字，映射到有限个低精度数字上。

例如：
模型原始权重：BF16
部署权重：INT4
这就是大家通常说的“4-bit 量化”。

原始浮点权重
    ↓ 除以 scale 并取整
INT4 数值
    ↓ 乘回 scale
近似的浮点权重


例如：
原始值：0.63
scale：0.1

0.63 / 0.1 = 6.3
取整 → 6

恢复：6 × 0.1 = 0.6

所以你会发现，其实Int4是用来储存的（同时还要保存缩放因子scale），实际计算的时候还是要回到FP16的


## 2 GPU
### 2.1 查看GPU状态
nvidia-smi 是查看GPU状态的命令
1Gb约等于1000mib=10^9 bytes

显存使用率高不代表GPU利用率也高

### 2.2 以一个例子为例研究GPU
在大模型训练和推理过程中，一张图片从硬盘走向GPU，中间每一步到底发生了什么

- 硬盘
  机械硬盘 HDD 类似留声机，速度很慢，便宜，容量大
  固态硬盘 SSD 超大号U盘，速度快非常多（放训练数据）
- 内存
  一断电就清空，但是非常快，是暂时的工作台
  数据到固态硬盘，然后到内存，然后CPU干活
  一张图片在硬盘，不能直接到GPU，要先让CPU解码，转成一个张量（tensor）
- GPU
  显存：显卡上的内存
  计算核心：不计算的话了利用率就是0了

固态硬盘类似于冰箱，把菜拿出来去放到内存里面去，CPU负责切菜，然后放到GPU里面去炒菜。

但是在实际过程中到处都是坑。有三条线会堵住
- 第一条，从硬盘到内存。Pytorch中有一个函数叫dataloader，里面有一个参数叫num_workers，默认是0，比如是8，就是有八个人从冰箱里面拿食物。这里有一个速度的问题
  磁盘I/O速度，从硬盘读到内存
  CPU解码速度
- 第二条，内存到显存，学名叫PCIE。如果batch size比较大，也会堵住。CPU将预处理好的数据从系统主内存通过PCle总线传输到GPU显存。例如PCle带宽是16GB/s。如果把张卡共享同一根PCle swith，总贷款就会被争抢。
  同步传输和异步传输
  
- 第三条，从显存到计算核心。GPU里面太快了，内部不同地方都有所差异。
  假设数据已经从内存通过PCle进入了Vram，GPU需要吧显存里面的数据版搬运到他的计算核心--SM（流式多处理器）内部的寄存器中，才能执行运算。
  
  主要瓶颈:显存带宽，虽然他比内存带宽大很多，但是相比于GPU还是很慢，
