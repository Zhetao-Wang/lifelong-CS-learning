## 2. 什么是端口？

### 2.1 端口的作用

可以把一台电脑想象成一栋大楼：

| 网络概念 | 类比 | 作用 |
| --- | --- | --- |
| IP 地址 | 大楼的地址 | 定位一台计算机 |
| 端口号 | 大楼里的房间号 | 区分不同的网络服务 |
| 服务 | 房间里提供的业务 | 响应网络请求 |

例如：

```text
192.168.1.10:80
```

表示访问 IP 地址 `192.168.1.10` 上的 `80` 号端口。

一台电脑可以同时运行多个网络服务，端口用于区分这些服务。

### 2.2 公网 IP 与内网 IP

```text
互联网
  ↓
路由器（公网 IP）
  ↓
你的笔记本（内网 IP，例如 192.168.1.5）
```

### 2.3 客户端与服务器的端口通信

你访问网站时：

```text
你的电脑:52000  →  网站服务器:443
```

- `443` 是对方的“房间大门”，表示你要访问 HTTPS 服务。
- `52000` 是你电脑临时使用的端口，方便网站把数据回传给你。

网站回复时，方向反过来：

```text
网站服务器:443  →  你的电脑:52000
```

### 2.4 什么是监听？

“监听”就是：某个程序正在某个端口上等待网络连接。

例如你启动了一个网站服务：

```text
程序 → 监听 8080 端口
```

意思是它在说：

> 如果有人访问我的 8080 端口，我准备接收请求。

也可以把它想象成：

- 端口：房间号
- 程序：房间里的工作人员
- 监听：工作人员守在门口等人

如果没有程序监听端口，即使端口号存在，也没有服务回应。

## 3. 访问网站的完整流程

以这个 URL 为例：

```text
https://example.com/news?id=1
```

完整流程大致如下。

### 3.1 浏览器解析 URL

浏览器先拆分 URL：

```text
https://example.com/news?id=1
│       │           │
协议    域名        路径和参数
```

因为没有写端口，所以 HTTPS 默认使用服务器端口 `443`。

如果是：

```text
http://example.com
```

默认端口通常是 `80`。

### 3.2 查询域名对应的 IP

浏览器需要知道 `example.com` 对应哪台服务器，于是进行 DNS 查询：

```text
example.com → 93.184.216.34
```

这个过程类似于先把“网站名字”查成“服务器地址”。

浏览器、操作系统或路由器可能已经缓存了结果，因此不一定每次都重新查询。

### 3.3 发起网络连接

假设你的笔记本 IP 是 `192.168.1.5`，系统随机分配一个临时端口，例如 `53124`：

```text
192.168.1.5:53124 → 93.184.216.34:443
```

其中：

- `53124`：你电脑临时使用的端口。
- `443`：网站服务器提供 HTTPS 服务的端口。

### 3.4 路由器进行转换

你的电脑通常没有公网 IP，所以请求会先到路由器。路由器会把它转换成公网地址，例如：

```text
192.168.1.5:53124
        ↓
公网 IP:62001
```

然后再通过运营商网络发送到互联网。

### 3.5 建立安全连接

因为使用的是 HTTPS，浏览器会先和服务器建立加密连接。

服务器会证明自己的身份，双方协商加密方式。之后，传输内容会被加密，别人通常无法直接看到你发送的网页请求和收到的网页内容。

### 3.6 浏览器发送 HTTP 请求

连接建立后，浏览器会发送类似这样的请求：

```http
GET /news?id=1 HTTP/1.1
Host: example.com
```

意思是：请把 `example.com` 网站下的 `/news?id=1` 资源发给我。

### 3.7 服务器处理请求

服务器上可能有一个 Web 服务程序正在监听 `443` 端口：

```text
Web 服务程序 → 监听 TCP 443 端口
```

它收到请求后，会：

- 判断要访问哪个网站。
- 读取网页文件。
- 查询数据库。
- 执行业务代码。
- 生成响应内容。

这里的“服务器”也可能不是一台机器，而是由 CDN、负载均衡器和多台后端服务器组成的系统。

### 3.8 服务器返回响应

服务器返回类似这样的内容：

```http
HTTP/1.1 200 OK
Content-Type: text/html
```

后面是网页 HTML 内容。数据按照原路返回：

```text
服务器:443
    ↓
你的路由器
    ↓
你的电脑:53124
```

路由器根据之前记录的连接，把数据交给你的笔记本。

### 3.9 浏览器继续加载网页资源

HTML 页面里可能还引用了：

- CSS 样式
- JavaScript
- 图片
- 视频
- 字体
- 其他接口数据

浏览器会继续请求这些资源。它们可能来自同一个服务器，也可能来自其他域名和服务器。

最后，浏览器把这些内容组合起来，显示成你看到的网页。

## 4. 整体流程总结

```text
输入 URL
  ↓
解析域名
  ↓
DNS 查询 IP
  ↓
本地临时端口 → 服务器 443 端口
  ↓
建立 HTTPS 加密连接
  ↓
发送 HTTP 请求
  ↓
服务器程序监听并处理
  ↓
返回网页数据
  ↓
浏览器渲染页面
```

> 最核心的一句话：
>
> URL 指定“访问哪个网站、哪个资源”；IP 找到服务器；端口找到服务器上的网络服务；HTTP 负责具体请求和返回内容。
